#+TITLE: doclive NEWS - user-visible changes

* 1.3.0 (2026-09-11)

  - The in-Emacs xwidget preview now opens in another window via
    ~display-buffer~, controlled by the new
    ~doclive-xwidget-display-buffer-action~ (default: to the right of the
    document window).
  - Re-running ~doclive-preview-buffer~ on the same buffer reuses its
    existing preview buffer instead of opening another xwidget session;
    restarting the server (~C-u~ prefix or ~doclive-stop-server~) points the
    reused preview at a fresh bootstrap URL.
  - The xwidget preview buffer is renamed from the page title, which the
    server now sets to "<document buffer name> - doclive" when it serves
    the page, so multiple previews stay distinguishable.  The name is set
    at first load and does not follow later in-page link navigation to a
    different document.
  - Preview buffers enable a buffer-local ~doclive-xwidget-preview-mode~
    that remaps copy (~M-w~, and ~s-c~ on macOS) to
    ~doclive-xwidget-copy-selection~ and yank (~C-y~, ~s-v~) to
    ~doclive-xwidget-yank-to-search~, so your usual copy/paste keys copy
    selected preview text to the kill ring and search the preview page.
  - Killing the previewed document buffer, or disabling
    ~doclive-preview-mode~ in it, now also closes the xwidget preview buffer
    it opened; ~doclive-stop-server~ still leaves preview buffers open.
  - The code-block Copy button now falls back to a selection-based copy when
    the asynchronous clipboard API is unavailable, so it also works inside
    the xwidget preview.
  - A single newline inside a paragraph no longer forces a line break,
    matching how GitHub renders Markdown files; two trailing spaces or a
    trailing backslash still force one.
  - The reading column widened from 840px to 1080px; wide tables scroll
    horizontally instead of overflowing, inline code inside table cells no
    longer wraps mid-token, task-list items no longer show a bullet beside
    their checkbox, and table headers keep their original case.
  - Mermaid diagrams render at natural size inside a scrollable frame capped
    at 70% of the viewport height, with per-diagram Fit / 100% / Expand
    controls; Expand opens a full-viewport overlay with mouse-wheel zoom and
    drag panning, closed by its close button, a click on the backdrop, or
    Escape in an external browser.  Inside the xwidget preview, key presses
    go to Emacs rather than the page unless ~xwidget-webkit-edit-mode~ is
    enabled, so use the close button or backdrop there.  Mermaid's theme now
    follows the page's dark/light theme.

* 1.2.0 (2026-07-26)

  - Unchanged Org buffers reuse their exported preview content, avoiding
    repeated full-buffer copies and Org HTML exports while preserving live
    revision broadcasts.
  - Opening a linked document no longer performs two snapshots before its
    first preview.
  - Release checks now validate the embedded preview JavaScript, exercise
    search, pin, theme, zoom, and status behavior in a real browser, and verify
    packaged release assets.
  - Preview status updates are announced to assistive technology, decorative
    status indicators are hidden from it, and pinned-highlight removal controls
    have descriptive labels.
  - Continuous integration now tests the supported Emacs 30.2 release.

* 1.1.0 (2026-07-11)

  Initial release.

  - Modern preview UI: compact monospace toolbar, Emacs-style bottom modeline
    with connection state and scroll position (Top/NN%/Bot), table-of-contents
    scroll spy, refined dark and light themes, and a focused reading column.
  - KaTeX math layout and Mermaid diagram styling are no longer blocked by the
    Content-Security-Policy: ~style-src~ allows inline styles for the trusted
    KaTeX/Mermaid runtimes, while the sanitizer strips ~style~ elements and
    ~style~ attributes from document-derived HTML before DOM insertion.
    Inline scripts remain nonce-only.
  - The default highlight.js asset URL now loads the browser bundle from
    ~@highlightjs/cdn-assets~ instead of a CommonJS build that failed in
    browsers.
  - LaTeX ~\(...\)~ and ~\[...\]~ delimiters emitted by Org HTML export are
    now recognized by KaTeX, so Org inline and display math render.
  - Documents opened through in-preview link navigation now join the live
    preview, so edits to the linked buffer push updates as well.
  - A bind failure at server start (for example a busy port) now reports an
    actionable error naming ~doclive-port~ instead of a raw process error.
  - Percent-encoded query values decode as UTF-8, so linked navigation to
    non-ASCII file names works on every platform.
  - Session tokens and CSP nonces read /dev/urandom directly when available
    instead of spawning an openssl subprocess per request.
  - ~doclive-stop-server~ also releases tracked buffer entries.
  - All customization options declare ~:package-version~ metadata.
  - Security: Org export now rejects ~(eval …)~ macros, ~#+INCLUDE:~, and
    ~#+SETUPFILE:~ directives before rendering, so previewing an untrusted
    document cannot execute Emacs Lisp or read arbitrary local files.
  - Security: the pinned default browser assets carry Subresource Integrity
    hashes, so a CDN compromise cannot substitute the preview scripts.
  - Security: connections that do not finish their HTTP headers in time are
    closed, and concurrent SSE clients per buffer are capped.
  - Security: browser requests reporting a cross-port ~Sec-Fetch-Site~ are
    rejected, since loopback ports do not provide site isolation.
  - Live preview of Markdown and Org documents via embedded HTTP server with SSE.
  - In-buffer preview using xwidget WebKit; falls back to external browser when xwidget is unavailable.
  - Markdown rendering via marked.js with syntax highlighting (highlight.js).
  - Org rendering via Emacs built-in ~org~ and ~ox-html~ (no Babel execution during preview).
  - Mermaid diagram rendering (backtick and tilde fences, ~mmd~ alias).
  - KaTeX math typesetting with LaTeX environment support
    (~equation~, ~align~, ~gather~, ~cases~, ~Bmatrix~, ~vmatrix~, and more).
  - TOC sidebar for document outline.
  - Code block copy buttons.
  - Full-text search with pin-based result highlighting.
  - Dark and Light theme toggle.
  - Zoom in/out controls.
  - Local relative link navigation between =.md= and =.org= files, with back/forward support.
  - Debounced snapshot updates (150 ms) for smooth editing without CPU spikes.
  - Cookie-protected local preview endpoints for preview, content, link opening, and SSE.
  - Initial preview URLs use short-lived single-use bootstrap codes and redirect to token-free preview URLs.
  - Preview API and SSE requests use an HttpOnly SameSite session cookie instead of query tokens.
  - Preview buffer IDs exposed to URLs, SSE streams, and JSON payloads are
    opaque per-buffer random routing identifiers, not local path or buffer-name
    derivations.
  - Referrer suppression and nosniff headers on local HTTP responses.
  - Inline preview runtime scripts and styles use response-local CSP nonces separate from the session cookie.
  - HTTP request parsing accepts only GET origin-form paths.
  - SSE responses also send no-referrer, nosniff, and no-store cache headers.
  - Local linked document navigation stays under the source file directory by default.
  - Preview commands and linked-document navigation disable local-variable evaluation while opening files.
  - Validation for host, port, debounce delay, and customized browser asset URLs.
  - Browser asset URLs are escaped before HTML embedding; malformed authorities,
    userinfo, non-numeric ports, and active-content schemes are rejected.
  - Browser asset URL authorities reject malformed DNS labels such as empty
    labels and leading or trailing hyphens.
  - Rendered document URL attributes are allowlisted before DOM insertion; form
    actions, media posters, and unparsed srcset lists are covered.
  - Linked-document resolution rejects protocol-relative URLs consistently with
    browser-side navigation.
  - Browser-side linked-document navigation rejects backslash-containing paths
    before they reach the local preview server.
  - HTTP query parameters with malformed percent-encoding are rejected instead
    of being interpreted as raw route data.
  - Malformed or duplicate preview-session cookies are rejected instead of being
    accepted as route authorization material.
  - HTTP response bodies are emitted as UTF-8 bytes before computing Content-Length.
  - SSE broadcast drops failed clients while continuing delivery to healthy clients.
  - Empty SSE client sets are removed instead of leaving stale tracking entries.
  - Content JSON no longer exposes source file paths to the browser runtime.
  - Preview URLs now use short-lived single-use bootstrap codes instead of
    exposing the long-lived session token.
  - Session lifecycle management: buffer-kill cleanup, preview-mode disable cleanup, server-stop token invalidation, Emacs shutdown hook.
  - Release gate includes byte-compilation, ERT tests, checkdoc, package-lint,
    autoload generation, daemon HTTP smoke testing, whitespace checks, secret
    scanning, and GitHub Actions security checks.
  - Customizable host, port, browser-open function, and debounce delay.
  - Interactive commands: ~doclive-preview-buffer~ (C-u to restart server),
    ~doclive-preview-file~, ~doclive-stop-server~, ~doclive-reload-page~.
