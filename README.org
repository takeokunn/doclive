* Overview

doclive is a live-preview Emacs package that renders Markdown and Org
documents in an xwidget WebKit buffer inside Emacs (or an external
browser as a fallback).  Edits are pushed to the preview in real time
over Server-Sent Events, so the rendered page stays in sync while you
type, with no manual refresh.

It is built for reviewing AI-generated documents: Mermaid diagrams and
LaTeX math environments render without extra setup.

* Features

- Live updates over SSE with a 150 ms debounce
- In-Emacs preview via xwidget WebKit, opened in another window next
  to the document (configurable placement) and reused on repeat
  previews of the same buffer, falling back to an external browser on
  Emacs builds without xwidget support
- Copy selected preview text and search the preview page using your
  usual copy/paste keys, from inside the xwidget preview buffer
- Markdown and Org rendering (Org exports through built-in =ox-html=,
  never executing Babel blocks); a single newline inside a paragraph
  does not break the line, matching GitHub's rendering of =.md= files
- Mermaid diagrams (backtick and tilde fences, =mmd= alias) at natural
  size in a scrollable frame with Fit / 100% / Expand controls and a
  full-viewport zoom-and-pan overlay
- KaTeX math, including LaTeX environments such as =equation=, =align=,
  =gather=, =cases=, =Bmatrix=, and =vmatrix=
- Syntax highlighting via highlight.js
- Local relative-link navigation between =.md= / =.org= files with
  back/forward history
- TOC sidebar, code-copy buttons, full-text search with pinned
  highlights, dark/light theme toggle, zoom, connection indicator
- Automatic cleanup on buffer kill and Emacs shutdown; killing a
  previewed document buffer, or disabling =doclive-preview-mode= in
  it, also closes the xwidget preview buffer it opened

* Installation

Requires Emacs 29.1 or later.

** MELPA

Once doclive is available on MELPA:

#+begin_src emacs-lisp
(require 'package)
(add-to-list 'package-archives '("melpa" . "https://melpa.org/packages/") t)
(package-initialize)
(package-refresh-contents)
(package-install 'doclive)
#+end_src

** use-package

#+begin_src emacs-lisp
(use-package doclive
  :commands (doclive-preview-buffer doclive-preview-file doclive-stop-server doclive-reload-page))
#+end_src

** From a source checkout

#+begin_src emacs-lisp
(add-to-list 'load-path "/path/to/doclive")
(require 'doclive)
#+end_src

* Usage

| Command                   | Description                                              |
|---------------------------+----------------------------------------------------------|
| =doclive-preview-buffer=  | Preview the current Markdown/Org buffer (=C-u= restarts the server first) |
| =doclive-preview-file=    | Prompt for a =.md= / =.org= file and preview it          |
| =doclive-reload-page=     | Force-push the latest snapshot to the preview            |
| =doclive-stop-server=     | Stop the local preview server                            |

=doclive-preview-buffer= treats a buffer as Org when its major mode
derives from =org-mode= or its file name ends in =.org=, and as Markdown
otherwise.

** Keybindings

doclive deliberately ships no default keybindings, so it never clobbers
your keymaps.  Bind the commands you use to keys you prefer, for example:

#+begin_src emacs-lisp
(with-eval-after-load 'doclive
  (define-key markdown-mode-map (kbd "C-c C-v") #'doclive-preview-buffer)
  (define-key org-mode-map      (kbd "C-c C-v") #'doclive-preview-buffer))
#+end_src

*** Preview buffer keys

Each xwidget preview buffer doclive opens enables a buffer-local minor
mode, =doclive-xwidget-preview-mode=, that binds nothing on its own
keys.  The buffer is renamed from the previewed page's title, so its
name carries the document name.  The minor mode only remaps your
existing copy and yank keys so they act on the previewed page instead
of the empty xwidget buffer:

- =kill-ring-save= (=M-w=), and =ns-copy-including-secondary= (=s-c=)
  on macOS, remap to =doclive-xwidget-copy-selection=, which copies
  the text currently selected in the preview page to the kill ring.
- =yank= (=C-y=, =s-v=) remaps to =doclive-xwidget-yank-to-search=,
  which puts the head of the kill ring into the preview page's "Find
  in page" box and applies the highlight.

Every other key press in the preview buffer goes to Emacs, not to the
page, unless Emacs's own =xwidget-webkit-edit-mode= is enabled.

** Local link navigation

Clicking a relative link to a =.md= / =.org= file inside the preview
opens the target in the same doclive page.  Fragments and query strings
are ignored during file resolution; remote URLs and unsupported
extensions never open.  By default, link targets are confined to the
directory of the clicking document (checked against symlink-resolved
real paths).  To allow links that escape to parent directories (for
example =../notes.md=), enable
=doclive-allow-linked-document-parent-directory= for trusted documents
only.

** Stopping the server

#+begin_example
M-x doclive-stop-server
#+end_example

Stopping the server discards the current session cookie and any unused
bootstrap codes, so previously issued first-preview URLs cannot be
reused after a restart.

| =doclive-allow-non-loopback-host=                 | =nil=         | Allow binding to non-loopback hosts                            |
| =doclive-port=                                    | =39123=       | Bind port                                                      |

| =doclive-xwidget-display-buffer-action=           | =(display-buffer-in-direction (direction . right))= | =display-buffer= action placing the xwidget preview window |
| =doclive-change-debounce-ms=                      | =150=         | Debounce interval for change detection (ms)                    |
| =doclive-preview-asset-urls=                      | pinned CDN    | marked.js / KaTeX / Mermaid / highlight.js asset URLs          |
| =doclive-allow-linked-document-parent-directory=  | =nil=         | Allow linked-document navigation outside the source directory  |

* Security model

doclive starts a local HTTP server bound to =127.0.0.1= by default.

- The first preview URL carries a short-lived, single-use bootstrap
  code instead of a long-lived session token.  A valid bootstrap
  request sets an =HttpOnly= / =SameSite=Strict= =doclive-token= cookie
  and redirects to a token-free preview URL.
- The cookie intentionally omits =Secure= because the server is plain
  HTTP and loopback-only by default.  If you explicitly opt into a
  non-loopback host, treat that network path as trusted or provide
  transport protection externally.
- Subsequent =/content=, =/open=, and =/events= requests are authorized
  by the cookie, never by query tokens.  Requests carrying a =token=
  query parameter are rejected even with a valid cookie.
- Buffer IDs appearing in URLs, SSE streams, and JSON payloads are
  opaque per-buffer random routing identifiers.  They are not authorization
  secrets and are never derived from file paths or buffer names.
- Stopping the server discards the session token and unused bootstrap
  codes; a fresh token is generated on the next start.  Disabling
  =doclive-preview-mode= in a buffer removes its preview entry, SSE
  clients, and update timer.
- Avoid sharing first-preview URLs (they contain unused bootstrap
  codes) in logs, pasted output, or public screenshots.  Preview HTML
  and HTTP responses set =no-referrer= so bootstrap URLs are not leaked
  to external CDNs via the Referer header.
- The inline runtime script is allowed through a response-local CSP
  nonce (separate from the session cookie), and request lines accept
  only origin-form absolute paths.  Inline scripts are never allowed
  without the nonce.
- =style-src= allows inline styles because KaTeX and Mermaid position
  rendered output through generated style attributes and SVG style
  elements, which CSP nonces cannot authorize.  To keep untrusted
  documents out of that allowance, the sanitizer removes =style=
  elements and =style= attributes from document-derived HTML before DOM
  insertion; trusted Mermaid SVG output (generated with
  =securityLevel: strict=) keeps its own styles.  That SVG comes from
  Mermaid's renderer, not from the document: at =strict=, Mermaid
  encodes HTML in diagram labels and disables click directives, so
  diagram source cannot inject markup or handlers.
- The server serves no files from disk.  Its only routes are the
  preview page, =/content=, =/open=, and =/events=, so the only local
  files a document can reach are the =.md= / =.org= targets of relative
  links, confined as described under Local link navigation.

Binding to a non-loopback host makes the server reachable from other
browsers on the same network.  Change =doclive-host= only when needed,
set =doclive-allow-non-loopback-host= to non-nil explicitly, and never
hand preview URLs to untrusted parties.

Browser assets default to pinned CDN URLs.  =doclive-preview-asset-urls=
accepts your own mirror or a local origin, but only absolute =https:= /
=http:= URLs or same-origin relative URLs.  =file:=, =ftp:=,
=javascript:=, =vbscript:=, =data:=, protocol-relative =//= URLs, and
backslash-bearing URLs are rejected, and the Content-Security-Policy is
generated from the configured asset origins.

URL attributes produced from document content (=href=, =src=,
=xlink:href=, =formaction=, =action=, =poster=) keep only relative
links, anchors, and =http:= / =https:= URLs; =mailto:= is allowed for
=href= / =xlink:href= only.  Other schemes, protocol-relative URLs,
backslashes, and control/whitespace-bearing URLs are removed before DOM
insertion.  =srcset= is removed because it is a compound URL list.

Linked-document navigation is confined to the clicking document's
directory by default, checked after symlink resolution, so a link name
inside the directory that points at an outside file will not open.

See [[file:SECURITY.md][SECURITY.md]] for the reporting process and the list of boundaries
whose bypass counts as a security bug.

* Comparison with alternatives

- =markdown-preview-mode= / =grip= :: render Markdown only; doclive
  also renders Org, Mermaid, and KaTeX, and keeps both formats live
  over one SSE server.
- =org-preview-html= :: exports Org to a static file per change;
  doclive pushes incremental updates without touching the filesystem.
- doclive intentionally stays out of WebSocket transport, remote file
  fetch, Org Babel execution, and Org publishing pipelines (see
  [[*Scope][Scope]]).

* Development

The canonical local gate:

#+begin_src sh
make check
#+end_src

=make check= runs compile, test, lint, package-lint, autoloads, a
syntax check of the embedded preview JavaScript, a headless Chromium
smoke test of the preview page, security (secret scan, GitHub Actions
lint, workflow security scan), the daemon smoke test, and =git diff
--check=.  The browser smoke test needs a Chromium or Google Chrome
binary; set =CHROMIUM_BIN= when none is on =PATH=.  Use =nix develop=
to get all CLI tools, or run the same gates through =nix flake check= /
=pre-commit run --all-files=.

The daemon smoke test uses =example/sample.md= and =example/sample.org=
to exercise daemon startup, first bootstrap, cookie authorization,
=/content=, =/events=, =/open=, force restart, and shutdown:

#+begin_src sh
make smoke
#+end_src

CI additionally verifies the declared minimum Emacs version (29.1),
the latest stable release, and a development snapshot.

** Snapshot benchmark

Run the batch benchmark from the repository root:

#+begin_src sh
emacs -Q --batch -L . -l benchmark/snapshot.el
#+end_src

The harness builds a deterministic Org document of approximately 100 KB,
then measures one initial =doclive--snapshot-buffer= export and repeated
refreshes without source changes.  Its output includes the exact input size,
Emacs and Org versions, iteration count, and elapsed times.

These numbers describe only the snapshot/export path on the machine running
the command.  They depend on the Emacs and Org versions, hardware, operating
system, and current system load; they are not a cross-project or
cross-environment performance ranking.

* Troubleshooting

- *The preview opens an external browser instead of showing inside
  Emacs.* :: Your Emacs was built without xwidget WebKit support, so
  doclive fell back to =browse-url=.  Rebuild Emacs =--with-xwidgets=
  (and a WebKitGTK / WebKit backend) for the in-Emacs preview.
- *Diagrams, math, or highlighting do not render.* :: Mermaid, KaTeX,
  and highlight.js load from external CDNs in the browser; check the
  browser console and network log.  On an offline or proxied network,
  point =doclive-preview-asset-urls= at your own mirror, a local
  origin, or your proxy.
- *The server fails to bind.* :: The error names the port; set
  =doclive-port= to a free one.
- *Org Babel, =(eval …)= macros, =#+INCLUDE:=, or =#+SETUPFILE:= do
  nothing.* :: Org preview exports through built-in =org= / =ox-html=
  as an HTML fragment with those features refused, so that opening an
  untrusted document cannot run code or read local files beyond the
  document itself.
- *A relative link does not open.* :: Remote URLs and =.el= / =.html= /
  =.pdf= files are not linked-document targets, and targets outside the
  clicking document's directory are refused by default.
- *The server refuses to start.* :: Token generation requires
  =/dev/urandom= or an =openssl= binary; on platforms with neither (for
  example stock Windows without openssl on =PATH=), startup fails.
- *A large Mermaid diagram is unreadable.* :: Use the diagram's Fit or
  100% control to resize it in place, or Expand for a full-viewport
  overlay with mouse-wheel zoom and drag panning.  Close the overlay
  with its close button or a click on the backdrop.  In an external
  browser, Escape also closes it; inside the xwidget preview, Escape
  reaches the page only under =xwidget-webkit-edit-mode=.

* Scope

In scope (MVP):

- Markdown / Org preview
- Local relative-link navigation for =.md= / =.org=
- Mermaid, KaTeX, code copy, search / pinned highlights

Out of scope:

- WebSocket transport
- Remote file fetch
- Org Babel execution
- Org-roam, agenda, PDF export, Org publishing
